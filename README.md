# 📱 Smartphone Shop API & Frontend

Веб-приложение для управления каталогом смартфонов, разработанное в рамках экзаменационного проекта. Проект демонстрирует применение многослойной архитектуры, паттернов проектирования, контейнеризации и централизованного логирования.

## 🛠 Технологический стек

- **Frontend**: React (Vite), CSS-Modules, Axios
- **Backend**: Python 3.11, FastAPI, Pydantic, Uvicorn
- **СУБД**: PostgreSQL 15
- **Логирование**: Seq (структурированные логи)
- **Оркестрация**: Docker, Docker Compose

---

## 📐 Архитектура проекта (Layered Architecture)

Бэкенд-приложение разделено на четкие изолированные слои в соответствии с принципами SOLID:

1. **Слой представления (Presentation Layer)**: `app/main.py` — обрабатывает HTTP-запросы, валидирует входящие/исходящие данные через Pydantic-схемы (`app/schemas.py`).
2. **Слой бизнес-логики (Business Logic Layer)**: `app/services.py` — инкапсулирует бизнес-правила приложения. Внедряется в контроллеры через Dependency Injection (`Depends`).
3. **Слой доступа к данным (Data Access Layer)**: `app/repositories.py` — реализует паттерн *Repository*, изолируя механизм хранения данных от бизнес-логики.

---

## 🚀 Ключевые технические решения

- **Паттерн Repository & DI**: Архитектура построена на слабой связанности (Loose Coupling). Зависимости репозитория и сервиса автоматически связываются через иерархический механизм `Depends` в FastAPI.
- **Двухэтапная загрузка медиа**: Для исключения конфликтов декодирования байтов в Pydantic реализована двухэтапная схема. Сначала файл загружается на изолированный эндпоинт `/media/upload` (тип `multipart/form-data`), сохраняется на сервере, а затем его текстовый URL передается в общем JSON-пакете на `/items`.
- **Централизованное логирование**: Все HTTP-запросы автоматически логируются через Middleware бэкенда и отправляются в систему структурированного логирования **Seq** в формате JSON.

## 📦 Быстрый запуск инфраструктуры

Для запуска всего стека приложений (Frontend, Backend, DB, Seq) одной командой необходим установленный **Docker Desktop**.

1. Клонируйте репозиторий и перейдите в корень проекта.
2. Запустите оркестрацию контейнеров:
   ```bash
   docker compose up --build -d
   ```

### Доступные интерфейсы после запуска:

- **Клиентская часть (React)**: [http://127.0.0.1:5173](http://127.0.0.1:5173)
- **Интерактивная документация API (Swagger)**: [http://127.0.0](http://127.0.0)
- **Панель структурированных логов (Seq)**: [http://127.0.0.1:8081](http://127.0.0.1:8081)

## 🛑 Остановка проекта

Чтобы корректно остановить работу всех контейнеров и освободить порты, выполните:
```bash
docker compose down
```
